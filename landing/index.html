Finds space where you would not look

Roomy checks every project on your Mac, then the hidden caches your tools keep in ~/Library and ~/.cache. Sizes stream in as they are found, usually within a minute.

  • Projects: node_modules, .venv, target/, build output, Pods — Node, Python, Rust, Ruby, Go, Java, Swift, .NET
  • Tool caches: Xcode DerivedData and simulators, npm, pip and Homebrew caches, Docker images, Conda, pyenv
  • AI tools: Ollama and Hugging Face models, Claude, Cursor and Codex caches, agent session history — see the AI page
  • Agent leftovers on servers: OpenClaw build captures, crash dumps, Claude Code scratch dirs, a Trash nobody emptied
  • Every item says whether it comes back on its own: Safe, Review or Irreversible

Nothing is deleted until you say so

Untick anything you want to keep and see exactly how much space you get back before confirming. Project folders go to the Trash; Docker and Conda are cleaned with their own tools.

  • A plain-language label and a safety badge on every item
  • Trash, not rm: everything is restorable until you empty it
  • Irreversible items (Xcode Archives, Docker volumes, chat history) ask again

Safe by design Project artifacts use NSWorkspace.recycle() — the macOS Trash API. Irreversible items get an extra warning before deletion. Docker and Conda cleanups use their official CLI tools, not Trash.

The same for your servers and your agents

Disks fill up on CI runners and agent hosts too. Since 1.3.0 the same engine ships as roomy for macOS and Linux, so a machine can free its own space on a schedule, and an agent that hits "no space left on device" can fix it. Agents call it with --json, write a plan, and clean exactly what the plan lists. Nothing above the Safe tier is removed without a flag; irreversible items never are. Every removal lands in a tamper-evident audit log. Many machines? Roomy Fleet & Hub puts every host on one dashboard. 

brew install tdermendjiev/roomy/roomy        # or the .deb / .rpm on Linux
roomy scan --json                       # what could be reclaimed, as data
roomy scan --plan plan.json             # safe tier only, by default
roomy clean --plan plan.json            # Trash on macOS, quarantine on Linux

# Unattended, across hosts
roomy fleet policy init --profile agent-host --hub http://hub.internal:9478 --output /etc/roomy/policy.json
systemctl enable --now roomy-fleet@agent.timer
roomy hub serve                         # one dashboard for every host, see /fleet
curl -s localhost:9477/metrics          # Prometheus
  • Plan-file deletion: a caller never passes raw paths. Items that vanished are skipped; tiers are enforced at clean time.
  • Quarantine with retention instead of a Trash nobody empties on a headless host. roomy restore undoes.
  • Roomy Fleet: JSON policies, hash-chained audit log, Prometheus metrics, systemd units, offline license tokens. Free in community mode on any number of hosts; licensed with support for commercial fleets.
  • One rule catalog as data. Add your agent's cache directory in a JSON file, no release needed.

Questions

How much space will I get back?

On most developer Macs between 10 and 100 GB. node_modules across old projects and Xcode DerivedData alone are often tens of gigabytes, and a few local AI models add 20 GB more. Roomy shows the exact number before you delete anything.

Is there a Pro version?

No. The Mac app and the roomy CLI are free. Teams that run Roomy unattended on many servers can license Roomy Fleet, which adds a central dashboard and support.

Does it work on Apple Silicon?

Yes. Universal binary for Apple Silicon and Intel.

Do I need an account?

No. Download, install, and run locally.

What are system caches?

Fixed-path folders outside your repos — DerivedData, global npm/pip caches, Homebrew, Docker, and similar. Roomy scans them in pass 2 and lists them under System caches.

Is deleting DerivedData safe?

Xcode regenerates DerivedData on the next build. Roomy marks it Safe and describes each cache before deletion.

How is Roomy different from CleanMyMac or DaisyDisk?

General cleaners show you big folders and leave the decision to you. Roomy knows what the folders are: node_modules, virtual environments, build output, Xcode and Docker caches, AI tool storage. It tells you whether each one comes back on its own and ranks projects by how long they have been idle. Free, offline, and it only touches things that regenerate.

Does it clean up Cursor, Claude Code and Ollama?

Yes. Since 1.2.0 an AI coding tools category covers model stores (Ollama, LM Studio, Hugging Face), editor caches (Cursor, Claude desktop, Windsurf) and agent session history (Claude Code, Codex, Gemini CLI). Session history is marked Irreversible and never bulk-selected. See the AI page.

Is there a CLI, and does it run on Linux?

Yes. roomy is the same engine as the app, for macOS and Linux (a single static binary, .deb/.rpm/.apk, Homebrew, container image). It is built for agents: roomy scan --json never deletes, roomy clean --plan removes only what a plan file lists, and irreversible items are refused without an explicit flag. roomy fleet adds policy-driven unattended runs with an audit log and Prometheus metrics for many hosts.

Is Roomy open source?

The engine, the roomy CLI, Fleet and Hub are open source under the Apache 2.0 license at github.com/tdermendjiev/Roomy. Rules are JSON, so a missing cache is one pull request away. The Mac app is free but not open source.
