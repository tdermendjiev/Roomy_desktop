Where Claude Code stores its data on macOS

Claude Code keeps a transcript of every session so you can resume it later, plus snapshots of every file it edits so you can rewind. The desktop app adds sandbox VM images on top. None of it is cleaned up aggressively, and together it can reach 10 GB or more.

Applies to Claude Code CLI and the Claude desktop app on macOS. Last reviewed October 2026.

Find out how much Claude is using

du -sh ~/.claude
du -sh ~/.claude/* | sort -rh | head
du -sh ~/Library/Application\ Support/Claude/* | sort -rh | head

Claude Code CLI: ~/.claude

FolderWhat it holdsDelete?
~/.claude/projects/ One folder per project, named after the project path with slashes replaced by dashes. Inside are JSONL transcripts of every session. These power claude --resume and --continue. Usually the largest folder. Irreversible
~/.claude/file-history/ Snapshots of files before Claude edited them, used by /rewind. Irreversible
~/.claude/debug/ Debug logs, one per session. Never read unless you are filing a bug. Safe
~/.claude/paste-cache/
~/.claude/shell-snapshots/		 Pasted content and shell environment snapshots from past sessions. Safe
~/.claude/settings.json
~/.claude/CLAUDE.md
~/.claude/skills/, plugins/		 Your configuration, global instructions, skills and plugins. Keep

Built-in retention

Claude Code prunes old transcripts on its own after a retention period, controlled by cleanupPeriodDays in ~/.claude/settings.json. Lowering it is the simplest ongoing fix:

{
  "cleanupPeriodDays": 14
}

That only covers transcripts. Transcripts for projects you have deleted still stay until the period expires, and the retention does not apply to the desktop app's data below.

Claude desktop app: ~/Library/Application Support/Claude

FolderWhat it holdsDelete?
…/Claude/vm_bundles/ Virtual machine images used to run Claude Code in a sandbox from the desktop app. Multiple versions accumulate. Often the single largest item, 5–15 GB. Safe
…/Claude/claude-code-vm/ The working VM state for sandboxed sessions. Safe
…/Claude/Cache
…/Claude/Code Cache		 Chromium caches for the Electron shell. Safe

Quit the Claude app before deleting any of these. The VM bundles are re-downloaded the next time you start a sandboxed session, so expect a wait on first use afterwards.

The runaway temp file problem

Claude Code writes the output of background tasks to files in its temp directory under /tmp. There is no size cap, and there are public reports of a single output file growing to hundreds of gigabytes when a background command never stopped printing. If your disk fills up suddenly during a session, check there first:

du -sh /tmp/claude-*/ 2>/dev/null
ls -laS /tmp/claude-*/ 2>/dev/null | head

Stopping the session clears the task. The files themselves are safe to delete once no session is running.
